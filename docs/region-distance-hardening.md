# 지역 좌표 해석 보강 — 2026-09-20

## 범위

지역 수정 자체의 런타임 변경은 `lib/region-distance.ts`와 `lib/region-city.ts`의 신규 prefix helper뿐이다.
기존 가입·작성 화면, 저장된 프로필, 결제·인증·번호 공개 API/SQL, 후보 수·연령 조건·거리 구간·새로고침 횟수는 변경하지 않는다.
공유 거리 함수이므로 1:1 추천뿐 아니라 가까운 이상형/관리자 화면의 거리 정렬에도 수정된 좌표가 사용된다.
외부 지오코딩 API, DB 조회, 정기 작업을 추가하지 않는다.
같이 반영하는 별도 연령 검증과 최종 통합 검증 결과는 [dating-age-hardening.md](./dating-age-hardening.md)를 참고한다.

## 수정 내용

- `경기 안양시`와 `경기도 안양시`, `서울 강남구`와 `서울특별시 강남구` 등을 같은 좌표로 해석한다. 원래는 짧은 이름만 제거해 `도안양시` 등이 남아 시·군·구 조회에 실패했다.
- 띄어쓰기·시/군/구 표기와 `성남시 분당구`, `수원시 권선구` 같은 하위 구 포함 입력을 처리한다. 분당·판교·동탄·일산은 기존 상위 도시 좌표를 사용하며 동네의 정확한 좌표라고 간주하지 않는다.
- `부산 진구`의 기존 인식은 유지하고 `부산광역시 진구`도 같은 부산진구로 처리한다.
- 좌표표의 `경상/고성군`을 경남으로 구분해 강원 고성군 좌표를 덮어쓰지 않도록 수정한다. 근거: [경남 고성군청](https://www.goseong.go.kr/index.goseong), [강원 고성군 버스정보](https://bis.gwgs.go.kr/).
- 기존 자료의 `전라/광주시` 잘못된 중복 행은 거리 조회에서 제외한다. 이 행은 경기 좌표를 광주광역시 평균에 섞고 있었다. 경기 광주시와 광주광역시의 유효한 행은 유지한다.
- 정식 시·도명만 적은 경우도 기존 짧은 시·도명과 같은 대표 좌표를 사용한다.

## 복수·모호한 지역 정책은 보류

`서울/부산`, `서울 수원`처럼 복수 지역으로 판단되는 입력은 기존 조회·대체 처리 방식으로 되돌린다.
전체를 새롭게 위치 불명으로 분류하면 추천이 불리해질 수 있어 이번 패치에서 정책을 변경하지 않는다.
`강서구` 등 시·도가 없는 모호한 이름도 기존 동작을 유지한다. 기존 선택이 실제 거주지역이라고 검증된 것은 아니다.
사용자에게 두 지역 중 가까운 곳을 적용할지, 주 거주지역 한 곳을 따로 받을지 질문한 상태이다.

## 검증

- 현재 코드 기준 지역·추천·새로고침 문구·가까운 이상형 관련 172개 테스트 통과.
- 17개 시·도의 정식/약칭, 저장 좌표표의 인식 가능한 모든 시·군·구, 공백/붙여쓰기/구분자 조합을 반복 검증.
- 린트 통과.
- 배포된 커밋 `acfd7e4`에 이번 지역 변경만 복사한 분리 작업 폴더에서 최종 프로덕션 빌드·타입 검사 통과(308개 페이지 생성). 기존 middleware/Browserslist 경고는 남아 있으며 이번 변경으로 생긴 오류는 없다.
- 운영 활성 프로필 1,571건의 지역값만 읽어 로컬 수정 전후 비교(쓰기 금지):
  - 시·군·구까지 인식: 788 → 1,090건.
  - 개선: 시·도 수준 301건 + 기존 미인식 1건.
  - 기존 시·군·구 인식에서 정밀도가 내려간 사례: 0건.
  - 같은 장소의 정식/약칭 차이로 잘못 계산되던 대표 4쌍 모두 거리 차이 0km.
  - 아직 미인식 7건: 광교 2, 마산·별내·재주·신촌·영통구 각 1. 위치를 임의로 만들어 넣지 않았다.
- 실제 운영 데이터로 추천 GET 경로를 로컬에서 읽기 전용 재현: 수도권 남성, 영남 남성, 호남 여성 3개 집단 모두 성공. 가까운·연령대 적합 후보가 충분할 때 기본/다음 추천 모두 10명 조건 충족. 새로고침 횟수 소비·회원 기록 수정·알림 발송 없음.
- 근거리 후보가 소진된 추가 후보에 먼 지역이 나오는 기존 정책, 후보 풀이 작을 때 일부 중복되는 현상까지 없애는 변경은 아니다.
