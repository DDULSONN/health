# 1:1 한마디 답장 — 로컬 검토본

## 동작

- 상단은 “○○님도 매칭을 수락했어요”와 기존 연락처 교환 버튼을 먼저 표시한다.
- 한마디와 답장은 선택형 인사로 아래에 둔다. 답장 대기·확인 기록 없음 같은 빈 상태는 표시하지 않는다.
- 실제 받은 답장은 부정적 답장을 포함해 교환 버튼 위에 표시한다. 답장을 결제 조건으로 추가하지 않는다.
- 신규 문구는 가벼운 인사/커피/운동 이야기 3개. 기존 전송 문구는 수정하지 않는다.

- 서로 수락하고 아직 번호교환 전인 매칭에서, 받은 한마디에 선택형 답장 1회.
- 문구: `좋아요, 연락 나눠봐요.` / `이번 주에 연락 가능해요.` / `지금은 어려울 것 같아요.`
- 보낸 답장은 수정하지 않으며 중복 클릭·응답 유실 후 재시도도 최초 답장을 반환한다.
- 답장은 상대 매칭 화면에 표시된다. 오래된 매칭도 상대의 새 답장이 있으면 현재 내역으로 보인다.
- 이 작업에서는 이메일·SMS 발송을 추가하지 않는다. 새로 불러온 매칭 내역에서 확인한다.
- 부정적 답장도 매칭 취소가 아니다. 결제·번호공개·추천·보상권 조건을 변경하지 않는다.
- 답장 전송 중/실패 여부로 기존 결제 버튼을 잠그지 않는다.

## 저장과 권한

- 별도 테이블 `dating_1on1_contact_nudge_replies`: 한마디 ID가 기본키. 문구 키와 서버 시각만 저장.
- 인증된 수신자만 POST 가능. 같은 출처 요청, 참여자, 차단/전화번호 차단을 API에서 검사.
- 서비스 전용 RPC가 매칭/한마디 잠금, 수신자, 매칭 상태, 결제 완료, 탈퇴/밴/회원 차단을 재검사.
- 기존 매칭/결제/번호/한마디/확인 시각은 갱신하지 않는다.
- SQL 미적용/답장 조회 오류 시 답장 기능만 숨기고 기존 내역/번호공개는 유지한다.
- 테이블과 함수만 추가하는 SQL: `supabase/sql/dating_1on1_contact_nudge_replies.sql`.
- 인사 문구 허용을 추가하는 SQL: `supabase/sql/dating_1on1_contact_greetings.sql`. 기존 키/문구·유일성·참여자/결제 상태 트리거와 권한 유지. 버전 RPC와 제약조건을 한 트랜잭션에 설치한다.
- 새 문구 SQL이 없거나 조회가 실패하면 기존 문구만 표시한다. 오래된 탭에서 새 문구를 전송해도 준비 중 안내로 안전하게 거절한다.
- 현재 운영 SQL·GitHub·배포는 적용하지 않은 검토본이다.

## 검증/로컬

- `node --test scripts/check-contact-nudge-reply.cjs`: 실제 라우트 + 로컬 PostgreSQL(PGlite), 권한/상태/재시도/미설치.
- `node --test scripts/check-contact-greetings.cjs`: 기존 메시지 보존, 신규/기존 전체 문구 저장·알림 한글, 구버전 호환, 권한, SQL 재설치.
- `node scripts/check-contact-nudge-reply-browser.cjs`: 실제 컴포넌트 → 라우트 → 로컬 SQL → 상대 화면, 320/390/768px.
- `node scripts/preview-contact-nudge-reply.cjs 3174`: 루프백 전용 가상 회원 미리보기.
- `node scripts/check-critical.cjs`: 기존 매칭·결제 회귀 테스트. 네트워크 차단 하에 실행.
- 토스 실결제나 운영 회원을 이용한 검증은 포함하지 않는다.
- PGlite는 단일 프로세스이므로 실제 운영 PostgreSQL의 다중 연결 잠금 경합 부하를 재현한 것은 아니다.

### 적용 절차

1. 로컬 UI 확인 후 답장 문구 승인.
2. 답장 SQL과 인사 문구 SQL 설치 및 권한 확인. 기존 읽음 SQL과 독립적이다. 인사 문구 SQL은 기존 한마디 테이블 설치가 선행되어야 한다.
3. 코드 배포 후 지정된 비운영 테스트 계정으로 양방향 확인.
4. 롤백은 코드만 되돌려도 기존 서비스 영향 없음. 답장 데이터는 보존한다.
