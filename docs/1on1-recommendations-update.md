# 1:1 후보 추천 개선 (2026-08-31)

## 변경 범위

- 기본 후보 최대 10명, 추가 후보 최대 3명. 기본/추가 목록 간 중복은 허용하지 않는다.
- 기본 후보에서 나이대에 맞는 후보를 먼저 최대 6명 확보한다. 전체 인원 대신 실제 조건에 맞는 인원을 센다.
- 지역/나이 조건이 비슷한 후보는 최근 7일의 1:1 활동, 신규 등록, 유효한 우선노출/플러스 등을 고려한다.
- 최근 활동은 후보 새로고침, 직접 지원, 상대 요청에 대한 응답 기록이다. 로그인 여부나 응답 확률을 의미하지 않는다.
- 같은 조건 내에서 날짜/새로고침 시각을 이용해 순서를 정한다. 정렬한 전체 목록을 회전시켜 지역 우선순위를 무너뜨리지 않는다.
- 새로고침 기준 시각은 24시간 동안만 적용한다. 무료 1회/플러스 2회 제한은 유지한다.

## 안전 조건

- 본인, 동성, 동일 인증 정보, 사용자/전화번호/연락처/관리자 차단, 명시적 거절 이력, 진행 중인 카드 쌍 제외는 유지한다.
- 프로필이 없거나 밴된 후보는 제외한다. 프로필 확인 실패 시 후보를 반환하지 않는다.
- submitted/reviewing/approved의 기존 후보 자격 정책은 바꾸지 않는다.
- 이전에 건너뛰었거나 취소/만료된 후보는 대안이 부족한 경우 기본 목록에만 다시 들어갈 수 있다.
- 최종 상세 조회에서 활성 상태를 다시 확인한다. 조회 중 성별/소유자가 바뀐 후보는 응답에서 뺀다.
- 전화번호, 차단 정보, 활동 시각, 내부 우선노출 필드는 후보 응답으로 보내지 않는다.

## 조회 방식

1. 내 활성 신청서가 없으면 바로 빈 목록을 반환한다.
2. 내 신청서 기준 이성 후보의 최소 선정 정보만 읽는다. 임의의 총 후보 수 제한은 두지 않는다.
3. 차단/밴/기존 매칭 등의 제외 조건과 추천 순위를 적용한다.
4. 최종 후보만 소개/사진 경로를 읽고 기존 이미지 프록시 URL로 변환한다.

회원 UUID 묶음은 200개로 제한해 긴 URL/응답 헤더 오류를 피한다. 차단 목록은 500건씩 끝까지 읽는다.
활동 조회는 이미 활동을 확인한 회원을 다음 조회에서 제외해 다량의 과거 지원 기록을 반복해서 읽지 않는다.

## 검증 및 적용

- 회귀 테스트: `npm run check:1on1-recommendations`
- 타입 검사: `npx tsc --noEmit --incremental false`
- 프로덕션 빌드: 프로젝트 환경변수를 로드한 뒤 `npm run build`
- 운영 DB 검증은 읽기 전용으로 진행한다. 별도 SQL이나 데이터 변경은 필요하지 않다.

## 남은 제약

- 과거 모든 노출 후보를 영구 저장하지 않는다. 후보가 적거나 조건이 같으면 이전 날짜/새로고침과 일부 겹칠 수 있다.
- 최근 활동이 없는 후보를 자동 탈락시키지는 않는다. 신청서 작성 시각만으로 잠수 여부를 단정하지 않는다.
- 이성 후보의 최소 정보는 여전히 전체를 읽는다. 대규모 성장 시 DB 내부 선정/집계가 후속 과제다.
- 이번 검증은 코드와 조회 안전성 검증이다. 실제 매칭률 향상이나 오류가 전혀 없음을 보장하는 것은 아니다.
