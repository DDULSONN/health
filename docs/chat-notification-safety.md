# 채팅·알림 화면 안정화 검증

## 변경 범위

- 채팅방을 바꾸면 이전 상세 조회를 취소하고, 취소 이후 도착하는 응답도 화면에 적용하지 않는다. A → B → A도 요청 세대로 구분한다.
- 선택된 방과 다른 대화는 렌더링하지 않는다. 해제된 실시간 구독의 늦은 이벤트도 무시한다.
- 채팅 상세 조회 실패 시 재시도를 제공하고, 내용을 확인하지 못한 방에는 전송하지 않는다.
- 전송·나가기·신고 응답이 늦어도 새로 선택한 방이나 작성 중인 내용을 덮지 않도록 화면 처리만 제한한다.
- 알림 조회의 HTTP/통신/응답 형식 오류를 빈 알림함으로 표시하지 않는다. 기존 목록·미읽음 수를 보존하고 재시도를 제공한다.
- 알림 클릭 시 읽음 PATCH를 기다리지 않고 내부 목적지로 이동한다. 읽음 실패 시 미읽음 상태를 유지한다.
- 읽음 중복 클릭과 읽음 처리/조회 간 경합을 막는다. 자동 재전송, 정기 폴링, 새 캐시는 추가하지 않는다.

1·2단계에서는 매칭 추천·수락·거절·연락처 교환·결제·번호 인증 및 채팅/알림 서버 API, DB/SQL을 수정하지 않았다. 이후 3·4단계의 채팅 조회 API 개선과 추가 검증은 `chat-profile-history.md`에 기록한다. 전송·읽음·신고·나가기 API는 두 단계 모두 변경하지 않는다.

## 로컬 검증 (2026-09-27)

- `npm run check:chat-notification-safety`: 32개 통과. 요청 취소/늦은 응답/타임아웃, 알림 응답·내부 링크 검증, 주요 서버 파일의 기준 커밋 `b1e6ad6` 대비 변경 없음 확인.
- `npm run check:chat-notification-browser`: 실제 두 React 화면을 StrictMode로 렌더링해 360px/1280px에서 총 50개 시나리오 통과.
  - 늦은 성공·404·503, A→B→A, 통신 지연·타임아웃·잘못된 방 응답, 재시도, 오래된 실시간 이벤트.
  - 정상 전송, 전송 실패/신규 방 생성/나가기/신고 완료 전 다른 방 선택, 종료 상태 갱신, 화면 이탈 후 응답.
  - 알림 최초 조회 실패/재시도/기존 목록 보존/정상 빈 목록, 읽음 응답 전 이동, 중복 클릭, 읽음 실패·재시도·타임아웃·화면 이탈.
  - 가로 넘침 및 브라우저 런타임 오류 없음. 모바일 오류 화면의 한글·버튼 배치도 이미지로 확인.
- 기존 `check:1on1-refresh-safety`, `check:1on1-contact-nudge` 통과.
- 기존 `check:dating-reports`: 48개 통과, 기존 evidence migration 테스트 1개 SKIP. 운영 SQL 검증을 의미하지 않는다.
- 변경 소스/테스트 대상 ESLint: 오류·경고 없음.
- 최종 `next build --webpack`: TypeScript 검사 포함 성공.

브라우저 검사는 테스트 계정·메시지만 사용하고 모든 API를 로컬에서 모의 처리한다. 외부 요청을 차단하며 운영 회원의 대화/알림/읽음 상태는 변경하지 않는다. 실제 SMS·결제·운영 Realtime 연결 검사는 수행하지 않았다. 통과한 검증이 모든 운영 환경의 무결함을 보장하는 것은 아니다.

## 재실행

브라우저 검사는 빌드된 `.next/static/css`가 필요하다. 프로젝트의 기존 브라우저 검사와 같이 Edge 및 로컬 Playwright 런타임을 사용한다. 다른 환경에서는 `CODEX_NODE_PACKAGES`를 해당 `node_modules` 경로로 설정한다. 캡처 파일은 실행 로그에 출력된 임시 디렉터리에 저장된다.

GitHub 반영/운영 배포 전에는 최종 빌드 성공과 변경 파일 범위를 다시 확인한다.
