# 1:1 추천 지역·신규 후보·추가후보 개선

## 확인한 문제

2026-09-16 제보 회원을 대상으로 읽기 전용으로 운영 데이터를 조회하고 실제
추천 GET 로직을 실행했다. 회원 이름·전화번호·사진은 이 문서에 저장하지 않는다.

- 추천 가능 요약 후보 534명 중 지역 거리 추정 90km 이내이면서 기존 나이 범위에
  맞는 후보가 120명인데, 기존 주 추천 10명은 모두 90km 밖이었다.
- 최근 7일의 새로고침 이력을 피하는 조건이 지역·나이 적합도보다 앞서서
  가까운 후보를 지나치고 전국의 아직 안 본 사람부터 고르는 구조였다.
- 정확한 거리와 나이 차이가 날짜별 섞기 값보다 우선하므로 추가후보도
  서로 다른 지역의 후보 사이에서는 날짜만 바뀌어도 고정되기 쉬웠다.
- 오늘 가입한 후보를 과거 새로고침 시점에도 존재했던 것처럼 재구성했다.
  새 프로필이 가상의 과거 추천에 포함되어 뒤로 밀릴 수 있었다.
- 추가 다각도 검사에서 24시간 만료 전환 오류도 재현했다. 화면은 날짜별 기본
  후보로 돌아갔지만 새로고침 계산은 지난 새로고침 페이지를 직전 화면으로 간주했다.
  같은 조건 후보 20명인 경우 다시 기본 후보 10명 그대로 반환할 수 있었다.

## 변경

- 지역·나이 적합도 단계 안에서 `미노출 → 이전 페이지 → 직전 페이지` 순으로
  재추천한다. 충분한 근거리·나이 적합 후보가 있으면 반복 방지 때문에 먼 곳으로
  넘어가지 않는다. 적합 후보가 부족하면 범위를 넓히며 후보를 영구 제외하지 않는다.
- 가까운 지역(기존 지역 좌표 기반 추정 90km 이내)과 기존 나이 범위를 최우선으로
  하고, 다음에는 가까운 지역의 나이 차이 6세 이내, 인접 지역의 나이 적합 후보 등으로
  단계적으로 넓힌다. 90km는 실제 이동 거리나 GPS 반경을 보장하는 값이 아니다.
- 비슷한 적합도·거리 구간·활동 상태·플러스 우선순위 안에서는 정확한 거리보다
  날짜/새로고침별 섞기를 먼저 적용한다. 같은 요청은 같은 결과를 반환한다.
- 최근 7일 등록된 근거리·나이 적합 프로필에 최대 2자리 진입 기회를 준다.
  이미 새로고침한 경우 마지막 새로고침 후 등록된 적합 후보도 최대 2명 반영한다.
  다른 사람이 새로 가입할 때마다 전체 목록을 바꾸거나 새로고침 횟수를 소모하지 않는다.
- 과거 이력은 당시 생성되어 있던 프로필로만 재구성한다. 과거 후보군이 작았어도
  현재 후보가 충분하면 10자리를 채운다.
- 오늘의 추가후보는 날짜뿐 아니라 최근 실제 새로고침 시점도 반영한다. 기존과
  마찬가지로 주 추천·찜·처리 이력과 중복되지 않는 후보에서만 최대 3명을 고른다.
- 새로고침 간격이 24시간 이상이면 해당 시점의 한국 날짜별 기본 화면을 재구성해
  그 목록을 피해 교체한다. 과거에 보았지만 이미 만료되어 화면에 없는 목록보다
  지금 기본 화면의 교체가 우선이다. 횟수 차감이나 만료 시간 자체는 바꾸지 않는다.

## 유지한 경계

반대 성별, 최신 본인/상대 프로필, 동일인 중복, 양방향 차단, 휴대폰 연락처 차단,
관리자 차단, 탈퇴·밴, 명시적인 거절, 진행 중 매칭 제외는 그대로 유지한다.
사진 상세 조회와 번호 공개·결제·매칭 수락 로직, 무료/플러스 새로고침 한도는
변경하지 않는다. 추가 DB 테이블·SQL·저장 작업·예약 작업은 필요 없다.

운영 회원에게 실제 새로고침을 실행하거나 사용 횟수를 초기화하지 않았다.
아래 비교는 실제 데이터로 계산한 결과이며 배포 완료 또는 실제 회원 화면의
확인 결과가 아니다. 개선 공지 게시 요청에 따라 추천 변경과 공지를 같은 배포에
포함하며, 다른 대기 중인 결제·휴대폰 인증 변경은 포함하지 않는다.

## 48시간 일회용 공지

- 기존 9월 8일 후보 새로고침 안내를 새 버전으로 교체한다.
- 공개 기간: 한국시간 2026-09-16 12:50:00부터 2026-09-18 12:50:00 직전까지.
- 제목: `1:1 매칭 후보 추천이 개선됐어요`
- 본문: `지역과 나이를 더 고려하고, 새로고침 시 후보가 반복되는 문제를 보완했어요.`
- 기존과 동일하게 매칭 관련 페이지·마이페이지에서 표시하고, 같은 브라우저에서
  확인하면 다시 표시하지 않는다. 이전 공지의 확인 기록은 새 공지를 막지 않는다.
- 회원별 첫 방문 시점부터 48시간을 세지 않고 공통 종료 시각을 사용한다.
  계속 열린 페이지·백그라운드 복귀·종료 직전 진입도 만료 후 공지를 숨긴다.
- 별도 cron/SQL/DB 조회 없이 종료된다. 소스 기록은 남지만 만료 후 화면에는
  공지와 배경 오버레이 모두 렌더링하지 않는다.
- `node --test scripts/check-site-announcement.cjs`: 기간 경계·재노출·다른 탭 확인·
  로컬 저장소 차단·페이지 이동·타이머 정리를 포함한 10개 검사.

## 검증

```powershell
node --test scripts/check-dating-1on1-recommendations.cjs

# 서비스 키는 기존 환경에서 읽으며 GET/HEAD 외 요청은 스크립트가 차단한다.
$env:AUDIT_ENV_DIR = '<승인된 환경 파일 디렉터리>'
$env:AUDIT_USER_ID = '<제보 회원 ID>'
node scripts/audit-recommendation-quality.cjs

# 남녀·수도권 나이대·충청/영남/호남/강원제주 12개 표본. 역시 읽기 전용.
node scripts/audit-recommendation-cohorts.cjs
```

- 78개 회귀 검사: 남녀 추천, 장기간 새로고침, 가까운 후보 고갈 방지,
  신규 프로필 반영과 이후 새로고침, 추가후보 변동, 주/추가/찜 중복 방지,
  소수 후보 재노출, 한도 유지, 읽기 전용, 차단·거절·탈퇴·동일인 안전장치.
- 만료 전환 신규 테스트를 먼저 추가해 실제 실패를 확인한 후 수정했다. 남녀 ×
  6개 지역 × 3개 나이대 × 후보 수 7종 × 8일 = 2,016개 상황에서 후보 수 유지와
  같은 적합도 내 가능한 최대 교체를 검증한다. 실제 GET 경로로도 자정 전후,
  24시간 만료, 플러스 연속 사용, 7일 이력 경계를 검증했다.
- 과거 테스트 중 "24시간 만료 후에도 지난 추천 페이지를 피해야 한다"는 가정은
  GET이 실제 보여주는 기본 페이지와 달랐다. 이 테스트는 실제 표시되는 기본
  페이지를 피하는지 검사하도록 교정했다. 동일 조건 충분한 후보의 교체 수 검사는
  유지하고 작은 후보군을 포함한 위 2,016개 조합으로 확대했다.
- 제보 회원 수정 후: 주 추천 10명, 추가후보 3명 모두 근거리·나이 적합 후보.
  다음 새로고침을 모의 계산했을 때 주 추천의 직전 목록과 중복 0명.
- 운영 조회 횟수는 전후 모두 35회였다. 거리 계산 결과는 단일 요청 안에서만
  재사용하고 회원/요청 간에는 공유하지 않는다.
- 운영 데이터 12개 표본을 실제 GET 계산으로 읽기 전용 재실행해 모두 성공했다.
  근거리·나이 적합 후보 10명 이상인 표본에서 주 추천/모의 다음 새로고침 모두
  적합 후보 10명을 반환했다. 12개 표본 중 직전 10명 전원이 반복된 표본은 없었다.
  호남 여성 표본은 적합 후보 12명이라 2명 교체·8명 재노출했고, 강원/제주 표본
  2건은 근거리 적합 후보가 각각 1명/0명이어서 확장 추천했다. 전국 모든 계정의
  무오류나 실제 UI 노출 로그의 검증을 의미하지 않는다.
- 로컬 합성 후보 2,000명·이력 14회·3번 평균 연산 측정: 기존 약 283ms,
  수정 후 약 47ms. DB/네트워크가 빠진 연산 측정이며 전체 사이트 속도나 요금의
  감소율을 뜻하지 않는다. 회귀 검사로도 후보당 거리 계산 1회를 확인했다.
- ESLint 오류/경고 없음. 수정 파일만 별도 작업 복사본으로 격리한 Next 프로덕션
  빌드와 타입 검사도 통과했다.

후보가 부족하면 일부 재노출은 여전히 가능하다. 과거 추천은 실제 노출 로그가
아닌 제한된 이력 재구성이므로 모든 상황에서 항상 10명 전원 교체를 보장하지 않는다.
