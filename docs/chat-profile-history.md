# 채팅 상대 프로필 / 이전 대화 조회

## 사용 흐름

- 채팅 상대 이름 옆 **프로필 보기** → 작은 창에서 해당 연결의 상대 정보와 기존 공개 설정에 따른 사진 확인.
- 클릭하기 전에는 프로필 API·사진 요청 없음. 창 닫기/Escape/상대 변경 시 요청을 취소하고 늦은 응답도 무시한다.
- 최근 대화 50개부터 표시. 위쪽 **이전 대화 보기**를 눌러 50개씩 더 불러온다. 과거 내용을 읽는 중에는 새 메시지 도착만으로 맨 아래로 이동하지 않는다.

## 권한과 호환성

- 프로필 조회는 서버에서 채팅 참여자, 내 숨김/종료 여부, 현재 연결의 수락 상태/양 당사자, 회원 존재·밴, 양방향 계정/연락처 차단을 확인한다.
- 오픈카드·대기 없이 등록·빠른매칭 각각 해당 연결의 카드/지원서만 조회한다. 임의 회원 ID로 프로필을 가져오지 않는다.
- 응답 필드를 명시적으로 제한하고 전화번호·이메일·인스타는 반환하지 않는다. 사진은 기존 인증 이미지 프록시를 사용하며 블러 사진을 원본으로 대체하지 않는다. 만료된 유료카드 사진은 기존 이미지 접근 제한을 유지한다.
- 프로필 조회 오류가 채팅 상세 조회·전송을 막지 않는다. 사진 로딩 실패는 깨진 이미지 대신 안내로 표시한다.
- `thread` API는 `paged=1`에서만 새 페이지 방식 사용. 기존 배포의 클라이언트는 기존 응답 형태 유지. 페이지마다 동일한 참여자/숨김 검사를 수행한다.
- `(created_at, id)` 순서와 해당 방의 메시지 ID 커서 사용. 서버가 커서의 시각을 조회하므로 동시각 메시지, 중간 신규 메시지 삽입으로 인한 offset 누락·중복을 피한다.
- 오래 자리를 비운 사이 최신 50개와 기존 화면이 겹치지 않으면 최신 구간으로 갱신하고, 중간 대화는 이전 페이지로 접근 가능하게 유지한다. 서로 떨어진 구간을 붙여 중간 대화가 없는 것처럼 표시하지 않는다.
- 이미 불러온 과거 대화는 최신 메시지 재조회 시 유지한다. 이전 페이지 조회 실패·중복 클릭·방 전환·최신 구간 갱신 후 도착한 옛 응답을 보호한다.
- 채팅방 목록은 모든 대화 본문 대신 기존 마지막 메시지 요약과 미읽음 메시지 ID만 조회한다. 미읽음 ID는 500개씩 이어 읽어 1,000개 기본 조회 한도로 개수가 잘리지 않게 한다.

DB 스키마/SQL, 매칭·결제·번호 인증, 채팅 전송/읽음/신고/나가기 API와 기존 이미지 접근 권한은 변경하지 않는다. SQL 추가 실행은 필요 없다.

빌드 산출물(service worker 등)은 코드 변경에 포함하지 않는다. GitHub 반영/운영 배포는 별도 승인 후 진행한다.
