# 카드 제한 안내 / 결제 실패 복귀

- 결제 전: 이번 반영 범위는 1:1 번호 교환의 공통 카드 제한 안내다. 무료 번호 교환에는 안내를 표시하지 않는다. 다른 구매 화면의 추가 안내 변경은 별도 대기 변경으로 남긴다.
- 결제 실패: 지원권은 충전 화면(기존 지원서 복귀 경로 유지), 지역 열람은 선택 지역으로 돌아간다. 번호 교환은 주문 당사자/PG 상태를 확인한 뒤 상대 프로필과 재시도 버튼을 표시하며, 확인이 어렵다면 기존 마이페이지/결제센터로 안내한다. 유료 카드·구독은 기존 결제센터의 이어하기를 사용한다. 실패 화면 진입만으로 주문 생성이나 자동 결제는 하지 않는다. 번호 교환 상세는 `docs/contact-payment-conversion.md` 참고.
- `failedOrderId`: 결제창 중단 시 Toss가 `orderId`를 전달하지 않을 수 있어 실패 URL에 기존 주문번호를 별도 이름으로 보존한다. 성공 URL, 승인, 금액 검증, 혜택 지급 로직은 변경하지 않는다.
- `/api/payments/toss/failure`: 로그인한 사용자의 최근 7일 주문만 확인하고 `payment_checkout_failures`에 주문당 첫 진단 이벤트만 기록한다. URL의 값은 **검증되지 않은 브라우저 제보**다. 결제 원장의 상태는 절대 변경하지 않는다.
- `PAY_PROCESS_CANCELED`는 사용자의 결제창 중단으로 별도 분류한다. 오류 코드만 저장하며 카드사, 전화번호, 이메일, 카드 정보, 원문 메시지, 결제 키는 수집하지 않는다. 이 데이터만으로 현대/국민/우리카드 사용 여부를 알 수 없다.

## 배포

DB 적재를 사용하려면 `supabase/sql/payment_checkout_failures.sql`을 적용한다. 서비스 역할만 읽기/쓰기가 가능하다. SQL 미적용 또는 기록 오류 시에도 구매 흐름은 유지되며 최소 진단 정보만 서버 로그에 남는다.

승인된 주문이 실패 제보와 함께 존재할 수 있다. 실패 통계는 결제 원장과 함께 확인해야 하며 환불·결제 취소 또는 중복 과금 여부의 근거로 단독 사용하지 않는다. 주문 삭제 시 진단 행도 함께 삭제된다.

## 검증

`node --test scripts/check-payment-recovery.cjs`

SQL 권한 검증은 `PAYMENT_RECOVERY_PGLITE_PATH`에 테스트용 `@electric-sql/pglite` 경로가 있을 때 함께 실행된다. 테스트에서 운영 PG 요청이나 실제 결제를 실행하지 않는다.
