# 1:1 후보 새로고침 잔여 횟수 안내

## 변경 범위

- 홈의 1:1 매칭과 마이페이지가 같은 문구 함수를 사용한다.
- 실행 전 확인창에 `사용 전 1회 → 이번 사용 후 0회`처럼 이번 요청 전후를 구분한다. 홈에도 동일한 확인창을 추가한다. 확인창 취소 시 API를 호출하지 않는다.
- 완료 안내는 화면의 기존 잔여 횟수가 아닌 성공한 POST 응답의 실제 `refresh_remaining`을 표시한다. 서버 오류·네트워크 오류 시 성공 문구를 표시하거나 자동으로 재요청하지 않는다.
- `24시간 이용 완료`를 `다음 이용 대기`로 변경한다. 소진 시 서버가 반환한 `next_refresh_at`을 한국 시간, 초 단위로 표시한다. 표시 시각은 초 단위로 올림하여 실제 이용 가능 시각보다 빨리 안내하지 않는다.
- 한국어 오전/오후를 직접 표시해 일부 런타임의 AM/PM 출력 차이를 없앤다. 자정 직전의 올림과 날짜 변경도 검사한다.
- 데이터가 아직 없으면 이용 상태 확인 중으로 표시하며, 만료 시각을 브라우저에서 추측하거나 버튼 권한을 자동으로 열지 않는다.
- 플러스 안내의 `하루 2회`를 `최근 24시간` 기준으로 통일하고 자정 초기화가 아님을 명시한다. 모바일에서 마이페이지 제목과 버튼이 겹치지 않도록 줄바꿈을 허용한다.

일반 1회/플러스 2회라는 서버 한도, 최근 24시간 계산, 이용권 유효기간, 새로고침 차감 RPC, 후보 선정, 사진, 매칭, 결제와 DB 데이터는 변경하지 않는다. 이용권 부여/횟수 초기화/운영 테스트 요청도 하지 않는다.

## 검증

`node --test scripts/check-dating-1on1-refresh-copy.cjs scripts/check-dating-1on1-recommendations.cjs`

- 문구·실제 화면 클릭 핸들러·렌더링 27개와 기존 추천 회귀 78개: 총 105개 통과.
- 무료/플러스 잔여 0·1·2회, 확인 취소, 서버 차감 후 잔여 횟수, 409 거절, 네트워크 오류, 기존 처리 중 가드, 로딩 상태, 잘못된 시각/횟수, 한국 시간의 자정 경계 검사.
- 테스트는 실제 TS/TSX 함수와 이벤트 핸들러를 가져와 가짜 응답으로 실행한다. 운영 계정의 새로고침 횟수를 소비하지 않는다.
- unrelated 결제/휴대폰 인증 작업을 제외한 HEAD 기반 별도 작업 사본에서 린트 오류 없음 및 `next build --webpack` 확인.

이 변경은 UI/안내 개선이며 지원 문의에 대한 설명은 별도로 전달했다. 깃헙 반영 및 배포는 사용자 요청 후 진행한다.
