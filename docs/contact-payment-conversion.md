# 1:1 연락처 교환 구매 동선

## 범위

1. 홈 1:1 탭과 마이페이지의 쌍방 수락 카드에 같은 안내/금액 표시.
   - `○○님과 서로 수락했어요`
   - `결제 완료 후 서로의 연락처가 공개돼요.`
   - `연락처 교환 · 20,000원`
   - 한 사람만 결제하면 된다는 설명은 펼쳐 보는 교환 안내에 유지.
   - 기존 연락처 교환 포함 플러스는 추가 결제 없이 기존 무료 처리 유지.
2. 연락처 교환 결제 실패 페이지에 당사자 프로필 이름/지역/사진과 재시도 동선.
3. 실제 받은 한마디가 있는 경우에만 보낸 사람과 원문을 결제 버튼 바로 위에 한 번 표시.
   보내기 횟수/동의, 알림/이메일 발송 동작은 변경하지 않음.

매칭 추천, 수락/거절, 전화번호 인증, 결제 승인/연락처 공개 함수와 기존 공개 기간은 변경하지 않는다.
정상 결제 버튼의 처리 함수는 유지하고 같은 매칭에 대한 연속 클릭만 ref로 차단한다.

## 결제 복귀 안전 장치

- URL의 제품/상대 정보는 권한 근거로 쓰지 않는다. 로그인 사용자의 주문으로 매칭을 찾고,
  당사자·쌍방 수락·회원 및 연락처 차단·연령·프로필 소유자·밴/삭제 상태를 확인한다.
- GET은 읽기 전용이며 private/no-store. 번호, 이메일, 결제 키, PG 원본 응답은 반환하지 않는다.
- Toss 주문 조회는 주문 ID/금액을 대조한다. DB paid, 교환 승인, PG DONE이면 재결제하지 않는다.
- IN_PROGRESS/WAITING_FOR_DEPOSIT, 수동 승인 대기, 환불/알 수 없는 상태, 조회 오류는 바로 재결제하지 않는다.
- 실제 클릭 시 서버에서 다시 확인한다. 같은 사용자의 READY 결제창은 같은 주문으로 재사용.
  ABORTED/EXPIRED는 기존 주문 생성 경로를 이용하므로 기존 금액/연령/Plus/중복 paid 검사가 유지된다.
- 상대방 주문을 포함한 최근 이력을 확인한다. 주문 8건 초과, 7일 초과 주문은 직접 재시도 대신
  기존 결제센터/마이페이지에서 확인하도록 한다. PG 조회 최대 8건, 각 5초 제한, 병렬 실행.
- 페이지 진입/새로고침으로 주문 생성·결제 승인·한마디 전송은 하지 않는다.
- 재시도 POST의 응답 유실/오류 뒤에는 즉시 다시 누를 수 없게 하고 내역 확인을 안내한다.
- 재시도는 기존 카드 결제창을 이용한다. PG 계약이나 결제수단 설정은 변경하지 않는다.
- 전체 결제 시스템의 동시성 구조를 바꾼 패치는 아니다. 별도 탭/기기에서의 모든 동시 결제를
  직렬화하는 DB 락이나 승인 절차 개편은 이 범위에 포함되지 않는다.

Toss API 근거: https://docs.tosspayments.com/reference (orderId 결제 조회/Payment 상태).

## 검증

- `check-contact-payment-conversion.cjs`: 실제 UI 렌더, 당사자/차단/삭제/연령/소유권,
  PG 상태별 응답, 실제 GET/POST 재검증, 새 결제 경로, 기존 버튼의 연속 클릭 방지.
- 기존 age, contact-nudge, payment-recovery, navigation 회귀 테스트와 함께 실행: 196개 통과, 건너뜀 0개.
- 별도 연락처 공개/권한 회귀 10개 통과. 최종 분리 작업 폴더에서 프로덕션 빌드·타입 검사 통과(310개 페이지).
- 실패 후 무료 교환 포함 혜택이 추가된 경우에도 유료 READY 결제창 대신 기존 무료 교환 경로를 사용함을 검증.
- PGlite에서 한마디 24시간 전환 및 결제 실패 진단 테이블 SQL의 권한/재실행 검증.
- `check-contact-conversion-browser.cjs`: 실제 컴포넌트와 빌드 CSS로 320/390/768px,
  가로 넘침, 원문 중복, 클릭/취소, 사진 로드 실패, 결제 버튼 연타, 오류·승인·진행 중 화면 확인.
  API는 전부 로컬 fixture로 가로채므로 실제 결제/전송이 발생하지 않는다.
- 운영 주문 3건 읽기 전용 확인: ABORTED/READY/DONE 주문 조회 정상, 주문 ID 일치,
  checkout URL 호스트가 허용된 Toss 도메인임을 확인. 결제 승인/주문 변경 없음.
- 실제 카드로 승인하는 실결제와 실물 iPhone/Android 검사는 수행하지 않았다.

## 반영 주의

이번 결제 동선 자체는 새 필수 DB 스키마가 없다. 기존 pending 변경을 임의로 일괄 커밋하지 말 것.
결제 실패 진단 로그 SQL은 별도(없어도 복귀 기능은 동작).
앞서 요청한 한마디 48→24시간 변경까지 함께 배포하려면
`supabase/sql/dating_1on1_contact_nudge_24h.sql`을 먼저 적용해야 한다.
2026-09-20 21:56 KST 운영 SQL Editor 읽기 검증: 함수는 이미 24시간이며,
기존 참여자/결제/취소 보호 조건, 활성 트리거 1개, security definer/search_path,
anon/authenticated 직접 실행 차단을 확인했다. 운영 함수/회원/결제 데이터는 수정하지 않았다.
선택적 진단 테이블은 아직 없으며 이번 운영 검증에서 생성하지 않았다.
