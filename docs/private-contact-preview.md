# 1:1 결제자 인스타 공개 — 검증 및 배포 안내

로컬 결제 승인은 가상 결제대행사이며 실제 토스 결제·출금 검증을 대체하지 않는다. 운영 적용에는 아래 SQL과 환경변수 설정이 함께 필요하다.

## 이용 흐름

1. 기존 연락처 교환 버튼 위에서 `내 번호 대신 인스타 공개`를 선택한다. 기본은 미선택이다.
2. 본인 인스타 아이디를 입력한다. 상대 번호는 결제자가 확인하고, 상대에게는 결제자의 인스타만 보인다는 안내를 제공한다.
3. 승인된 주문의 저장된 선택값으로 공개 방식을 결정한다. 승인 요청에서 연락처 선택값을 바꿀 수 없다.
4. 승인 후 해당 매칭의 `짐툴에서 대화하기` 버튼으로 양쪽이 대화한다.

일반 웹 유료 번호교환에만 추가된 선택 기능이다. 기존 번호교환, 교환권, 플러스 포함 무료 교환, 기존 할인 주문은 기존 방식을 유지한다. 인스타 주문 재개는 저장된 선택을 유지한다. 만료 주문 또는 플러스 무료 혜택이 새로 생긴 주문은 다시 선택하도록 안내한다. 지원하지 않는 경로에서는 인스타 선택을 명시적으로 거절하며 번호 공개로 자동 전환하지 않는다.

## 개인정보·결제 보호

- 상대에게 반환하는 API 응답에서 결제자의 전화번호를 제외한다. 화면만 숨기는 방식이 아니다.
- 공개 데이터 저장과 매칭 승인 상태 변경을 한 SQL 트랜잭션으로 처리한다. 저장 실패 시 인스타/전화번호 모두 새로 공개하지 않는다.
- 동일 결제 재확인은 멱등 처리한다. 다른 주문으로 기존 공개 방식을 덮어쓰지 않는다.
- 신규 옵션 사전 검증 실패 시 기존 결제 대기 주문을 취소하지 않는다.
- 일반 회원은 전용 테이블/RPC에 직접 접근할 수 없다. 채팅 읽기·쓰기마다 현재 매칭, 양쪽 계정, 차단, 결제 상태를 검사한다.
- 공개 설정 조회 실패 시 전화번호로 대체하지 않고 오류 처리한다. 신규 결제를 비활성화해도 기존 인스타 공개의 번호 보호는 유지한다.
- 인스타 아이디는 형식만 검증하며 소유권 인증은 아니다. 본인 계정 입력 안내를 제공한다.
- 사이트 내 번호 비노출과 별개로, 직접 전화·문자를 보내면 발신번호가 보일 수 있음을 안내한다.

## 로컬 검증

`scripts/preview-private-contact.cjs`는 실제 화면 컴포넌트·API 핸들러·SQL을 격리된 PGlite와 가상 결제대행사로 연결한다. 운영 인증정보를 읽거나 실제 회원에게 연락하지 않는다. 결제자/상대방 전환과 채팅 왕복을 확인할 수 있다.

관련 검사: `scripts/check-private-contact.cjs`, `scripts/check-private-contact-client.cjs`, 기존 결제 통합·교환권·한마디·결제 진단 검사. 빌드: `scripts/check-private-contact-build.cjs`의 격리된 Next 프로덕션 빌드.

실제 API 핸들러와 SQL로 결제자/상대방의 비대칭 공개, 중복·동시 승인, SQL 실패 롤백, 차단·탈퇴·환불, 주문 복구를 검사한다. 채팅은 한글·이모지 왕복, 중복 클릭, 응답 유실 후 같은 전송 ID 재시도, 오래된 조회 응답, 권한 만료, 화면 전환, 통신 시간 제한을 검사한다. 모바일 브라우저에서는 양방향 전송과 새로고침 후 대화 유지까지 확인한다.

## 운영 적용 및 확인 범위

- 신규 SQL `supabase/sql/dating_1on1_private_contact.sql` 설치와 신규 환경변수 `ONE_ON_ONE_INSTAGRAM_CONTACT_ENABLED=true`가 모두 필요하다. 기본값은 OFF다.
- `dating_1on1_private_chat_inbox.sql` 적용 후 기존 `/chat` 탭에서도 `1:1 대화` 목록으로 진입한다. 상대의 1:1 이름, 최근 메시지, 읽지 않은 수를 표시하며 기존 오픈카드·빠른매칭 채팅 구조는 유지한다. 기존 번호만 교환한 매칭에 새 채팅 권한을 만들지는 않는다.
- 새 메시지는 사이트 알림과 하단 채팅 배지로 안내한다. 알림을 누르면 해당 대화로 바로 이동한다. 이번 범위에는 이메일·문자·기기 푸시 발송을 포함하지 않는다. 알림에는 대화 내용·전화번호·인스타 ID·실명을 싣지 않는다.
- 수신자가 화면에 표시된 대화 하단을 실제 볼 때 마지막 표시 메시지까지만 읽음 처리한다. 백그라운드 조회는 읽음 처리하지 않으며, 그 사이 도착한 새 메시지의 배지는 남는다. 같은 전송 ID의 재시도는 알림도 중복 생성하지 않고, 연속 미확인 메시지는 알림 하나로 묶는다.
- 목록·배지도 현재 결제·취소·차단·회원 상태를 재검증한다. 새 SQL은 읽음 테이블·채팅 알림 트리거·서버 전용 목록/읽음 함수만 추가하며 기존 결제 승인 및 번호 공개 함수는 교체하지 않는다. 반드시 SQL을 먼저 설치한 뒤 코드를 배포한다. 과거 메시지에 알림을 소급 발송하지 않는다.
- 실제 토스 신규 결제 승인과 실제 회원 계정으로 결제 후 대화하는 운영 종단 간 검증은 수행하지 않았다. 기존 토스 승인 통신은 유지하며 공개 처리와 채팅 경계는 격리된 실제 핸들러·SQL 테스트로 검증한다. 배포 후에는 비로그인 차단, 캐시 방지 헤더, 배포 SHA, SQL 권한을 읽기 전용으로 확인한다.
- 채팅은 최근 100개를 조회하며 화면이 보일 때 15초 간격과 다시 돌아온 시점에 갱신한다. 동일 전송 ID는 중복 저장하지 않는다. 새 메시지는 회원당 1분에 20개까지 허용한다.
- 롤백은 우선 신규 옵션만 OFF로 한다. 인스타 공개 완료 건이 있으면 개인정보 읽기 보호 코드와 SQL을 제거하거나 이전 번호 공개 코드로 되돌리면 안 된다.
