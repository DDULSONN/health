# 통합 프로필 완성 올패스 할인

## 적용 범위

- 휴대폰 인증 완료, 정상 회원이며 오픈카드(pending/public)와 활성 1:1 프로필(submitted/reviewing/approved)이 모두 있어야 한다. 작성 경로가 달라도 현재 두 프로필이 완성된 회원은 포함한다.
- 홈 매칭 영역과 마이페이지 매칭탭 상단에 작은 안내를 표시한다. 이미 두 플러스를 모두 사용 중인 회원에게는 표시하지 않는다.
- 처음 안내가 보이는 시점부터 서버에 24시간을 한 번 저장한다. GET 조회만으로 시작하지 않으며, 재로그인·기기 변경·새로고침·SQL 재실행으로 연장되지 않는다.
- 30일 올패스 39,900원 → 32,000원(7,900원 할인, 할인율 약 19.8%이므로 화면에는 ‘약 20% 할인’으로 표시). 기간/추천/플러스 혜택은 기존 올패스와 동일하다. 번호 교환은 포함하지 않는다. 웹 Toss 결제용이며 앱스토어 상품 가격은 변경하지 않는다.
- 할인 안내가 활성화된 회원은 기존 올패스 버튼으로도 할인된다. 할인 ID를 포함한 결제 요청이 만료/무효라면 정가로 대체하지 않고 중단한다.
- 정상 구매는 한 번이며, 서버에서 주문 ID·금액·시간·회원 자격을 확인한다. 유효 주문은 재사용한다. 공급자가 EXPIRED/ABORTED라고 명확히 응답한 미결제 건만 새 주문으로 교체한다. 상태 불명·진행 중·환불 건은 새 주문으로 대체하지 않는다.
- 만료된 주문은 신규 승인하지 않는다. 이미 공급자 승인이 끝난 동일 주문은 만료 후에도 기존 지급 처리로 복구할 수 있다. 매칭/번호교환/사진 등록 로직은 변경하지 않는다.

## 배포

1. `supabase/sql/all_pass_profile_offer.sql` 설치(아직 운영 미적용). 별도 크론이나 메일 없음. 설치 자체는 회원별 기간 시작, 결제, 지원권/플러스 지급을 하지 않는다.
2. 코드 배포. SQL 미설치 시 안내를 숨기며, 기존 정가 구매 경로는 유지한다.
3. 운영자가 승인한 테스트 계정과 테스트 결제 환경에서 실제 Toss 왕복 확인 후 공개한다. 로컬 시험은 가상 결제이며 실결제 검증을 대신하지 않는다.

새 테이블은 anon/authenticated 접근을 막고 service_role은 SELECT와 제한된 함수만 실행한다. 기존 결제/회원 테이블의 권한·정책은 이 SQL에서 변경하지 않는다. 운영 결제 테이블의 기존 권한 보안 패치는 별도로 유지해야 한다.

## 검증

`node --require ./scripts/test-no-network.cjs --test scripts/check-all-pass-profile-offer.cjs`

`node scripts/check-all-pass-profile-offer-browser.cjs`

`npm run build`

가상 PostgreSQL(PGlite)에서 조건·재실행·중복 요청·주문 교체 롤백·24시간·권한을 확인한다. 병렬 호출은 PGlite에서 직렬 실행되므로 운영 다중 연결 부하 시험과 같지는 않다. 화면은 실제 컴포넌트, 가상 인증/API로 검사한다. 네트워크 장애 시 정가로 자동 전환하거나 자동 결제하지 않는다.

배포 필수 검사에 포함된 기존 소스 비교는 검증된 원본의 SHA-256을 사용한다. 과거 커밋을 포함하지 않는 shallow checkout에서도 동일한 비교를 생략하지 않고 실행한다.

로컬 화면: `node scripts/preview-all-pass-profile-offer.cjs` (기본 3143 포트, 실제 결제 없음).

결제 재시도 처리 참고: [토스페이먼츠 결제 흐름](https://docs.tosspayments.com/guides/v2/get-started/payment-flow), [API 오류 코드](https://docs.tosspayments.com/reference/error-codes).
