# 1:1 후보 새로고침 보강 및 최종 검증

## 배포 전 검증 범위

- 로컬 `codex/recommendation-repeat-safety` 작업. 기존 준비 커밋 `c7bea2b`에 후속 안전 장치를 추가했다.
- 2026-09-22 최종 검증 시작 시 원격 main 기준은 `252527e`. 이 문서는 배포 전 검사 기록이며 실제 GitHub 반영·배포 상태는 커밋과 배포 상태에서 확인한다.
- 별도 결제 보안 패치는 섞지 않았다. 실회원 새로고침/연락/결제/차감도 하지 않았다.

## 보강된 동작

1. 실제 후보 조회 결과가 화면 상태에 반영되어야 새로고침 완료를 안내한다. 실패하거나 더 최신 요청에 의해 취소된 조회는 성공으로 처리하지 않는다.
2. React 재렌더 이전의 연속 클릭도 동기 ref 잠금으로 1건만 전송한다.
3. 처리 결과를 확인하지 못했으면 추가 POST를 차단하고 GET 전용 ‘명단 다시 불러오기’를 제공한다. 실패 직후 이전 클릭 핸들러를 다시 실행해도 POST하지 않는다. 정상 명단을 반영하면 차단을 해제한다.
4. 빈 정상 목록은 허용하지만 잘못된 배열/빈 그룹/null 카드/객체형 사진 목록 등은 렌더링 전에 거절한다. 정상 응답이나 사진 주소를 변형하지 않는다.
5. 앞서 준비한 후보 이력 보강안으로 동일한 지역·나이 적합도 안에서 이전 추가 후보 대신 다른 후보를 우선 선택한다. 가까운 후보를 억지로 먼 후보로 바꾸지는 않는다.

## 검증 결과

- `npm run check:1on1-refresh-safety`: **326개 통과 / 실패 0 / 건너뜀 0**.
  - 추천 API 실제 응답이 새 화면 검증 규칙을 통과하는지 기존 API 사례마다 추가 확인.
  - 양방향 차단·연락처 차단·관리자 차단·밴·탈퇴·영구 거절·진행 중 상대 배제.
  - 성별/신원 중복, 나이/지역, 신규 프로필, 작은 후보군, 자정·24시간 경계.
  - 연속 클릭, POST 응답 누락, null/비정상 성공 응답, GET 실패/잘못된 중첩 응답, 취소된 조회, 실패 후 GET 복구.
- `npm run check:1on1-refresh-browser`: **실제 React 페이지의 로컬 브라우저 16개 시나리오 통과**.
  - 홈/마이페이지 × 폭 390/1280 × 정상 연속 클릭/조회 실패/잘못된 조회/POST 응답 누락.
  - 성공 안내 시점, 복구 버튼, 복구 후 후보·잔여 횟수, 새로고침 POST 1건 유지 확인.
  - JS 실행 오류 0, 실제 운영 요청 0, 가로 넘침 검사 통과, 한글 깨짐 문자 없음.
  - UI는 실제 페이지이며 인증·API·사진은 테스트 데이터. 실제 휴대폰 Safari/삼성인터넷 검증을 대체하지 않음.
- 기존 복구 SQL의 격리 PostgreSQL 검사 **4건 통과**. SQL 변경/운영 실행은 하지 않음.
- 현재 main과 보강안의 경계 비교 12건 재현: 기존 문제와 보강 후 개선을 각각 확인. 기존 문제 재현 assertion은 보강안 합격 테스트와 별개.
- 최종 production build 성공. 타입 검사 통과. targeted lint 오류 0, 페이지의 기존 unused/img 경고 12건은 남아 있음.

## 검사 과정에서 해결한 테스트 환경 문제

- 공통 페이지 콜백을 직접 실행하는 기존 테스트에 새 검증 함수/ref 바인딩이 빠져 실패했다. 테스트 입력도 숫자 배열 대신 실제 후보 응답 형태로 갱신하여 전체를 재검사했다. 검증 함수를 우회하는 mock으로 바꾸지 않았다.
- 독립 브라우저 번들에 사용하지 않는 서버 crypto 모듈이 따라와 테스트 번들 설정에서 제외했다. 앱 빌드 설정은 변경하지 않았다.
- 브라우저 fixture의 오픈카드 통계 응답에 남/녀 카운트가 빠져 발생한 테스트 화면 오류를 실제 API 형태로 보완했다. 앱 로직을 변경해 fixture 오류를 숨기지 않았다.

## 변경하지 않은 부분

원격 main과 diff 대조로 다음을 확인했다.

- 결제 API 전체, 휴대폰 인증 API, 1:1 선택·수락·거절·번호 교환 API.
- 새로고침 횟수 소비 POST/RPC 및 무료 1회/플러스 2회 정책.
- 사진 상세 로딩/서명 URL 코드, 기존 지역·나이 기준, 플러스 기간/가격.
- SQL/DB 스키마. 새 조회 API나 추천 DB 조회를 추가하지 않았다.

## 남는 한계와 반영 전 주의

- 적합 후보가 부족하거나 추가 목록에 남은 동급 후보가 딱 3명이면 반복될 수 있다. 13명 중 10명씩 두 번 보여주면 최소 7명 중복이다.
- GET 복구는 추가 횟수를 쓰지 않지만, 실패 전에 서버에서 정상 완료된 새로고침 1회까지 환원하는 기능은 아니다.
- 브라우저 잠금은 해당 화면 인스턴스의 중복 전송 방지다. 별도 탭/기기 간 요청의 정확히 한 번 처리나 불명확한 서버 처리 결과까지 해결하는 서버 idempotency 패치는 아니다. POST를 자동 재전송하지 않는다.
- 실제 회원 브라우저의 모든 네트워크 장애/기종·운영 로그를 검사한 것은 아니므로 ‘절대 오류 없음’으로 표현하지 않는다.
- 반영 직전 원격 main 변경 여부와 diff 범위를 다시 확인하며 별도 결제 보안 변경 및 진단 전용 파일은 제외한다.

## 재실행

```powershell
npm run check:1on1-refresh-safety
npm run check:1on1-refresh-browser
```

브라우저 검사는 기존 로컬 Edge/Playwright와 로컬 빌드 CSS를 사용한다. 서비스 인증정보를 읽지 않으며 모든 외부 요청과 지원되지 않는 쓰기를 차단한다.
