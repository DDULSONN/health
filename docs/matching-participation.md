# 1:1 첫 요청 · 받은 요청 안내

## 적용 범위

- 홈 1:1 탭의 작은 첫 요청 안내와 기존 받은 요청 안내 문구만 보완한다.
- 추천 순서, 새로고침 횟수, 요청/수락/거절 API, 결제 및 연락처 공개 조건은 유지한다.
- SQL 설치나 기존 회원 데이터 일괄 변경은 없다. 별도 문자·메일 캠페인을 발송하지 않는다.

## 첫 요청 안내

- 인증된 회원의 활성 프로필과 실제 표시 가능한 후보가 있고, 발송 이력이 없다고 확인된 경우에만 표시한다.
- 홈에서만 기존 `/api/dating/1on1/my?participation=1` 응답에 `has_sent_request`를 추가로 요청한다.
- 본인의 전체 발송 기록에서 `source_selected_at`이 있는 한 건만 조회한다. 취소·차단으로 목록에서 빠졌거나 오래된 프로필의 기록도 포함한다.
- 조회 실패/시간 초과/구버전 응답은 `null`로 처리하고 안내를 표시하지 않는다. 프로필·연락처 응답은 유지한다.
- 받은 요청이나 진행 중인 매칭이 있으면 해당 진행을 우선한다. 후보 없음·내린 프로필·미인증·조회 중/오류에는 안내하지 않는다.
- 작성 직후 기존 완료 안내와 중복 표시하지 않는다. 요청 API 성공 후 안내 상태를 즉시 갱신하며 실패 시에는 유지한다.
- `후보 확인하기`는 기존 추천 목록으로 스크롤/포커스만 이동한다. 새 요청·새 후보 조회·결제를 실행하지 않는다.

## 받은 요청 안내

- 기존 받은 요청 영역에서 첫 상대의 1:1 프로필 이름을 표시한다. 계정 닉네임과 혼동하지 않도록 한다.
- 프로필은 기존처럼 처음 3명만 펼친다. 접힌 상태는 `프로필 보기`로 다시 열고 수락/거절은 기존 버튼을 사용한다.
- 기존 요청 도착 알림을 간결하게 바꾸고, 수락만으로 결제/연락처 공개가 발생하지 않는다고 안내한다.
- 미응답 메일은 해당 요청의 프로필 이름과 정확한 매칭 링크로 연결한다. 이름 조회 오류는 일반 안내로 대체한다.
- 기존 24~48시간 구간, 09~20시 KST, 수신자별 최근 24시간 제한, 이벤트 중복 방지 키를 유지한다.
- 발송 직전 취소·차단·탈퇴·제재·수신 설정을 재확인하는 기존 보호 절차를 유지한다. 안내 이후 상태가 달라질 수 있음을 메일에 명시한다.

## 검증

- `node scripts/check-critical.cjs` — 기존 결제/번호공개 포함 로컬 회귀 및 SQL 검사.
- `node scripts/check-recommendation-refresh-browser.cjs --participation` — 실제 홈 컴포넌트와 가상 API를 사용하는 모바일/PC 시나리오. `TEST_BROWSER=webkit` 지원.
- `node scripts/check-dating-notification-email-browser.cjs` — 실제 메일 HTML 생성, 한글/링크/수신 설정 검사. 실제 발송 없음.
- `node scripts/check-recommendation-refresh-browser.cjs --engagement` — 기존 작성 완료/찜/받은 요청 경로 회귀.

운영 효과는 배포 후 요청 전환율과 응답률로 별도 확인해야 하며, 로컬 테스트로 매칭 또는 매출 증가를 보장하지 않는다.
